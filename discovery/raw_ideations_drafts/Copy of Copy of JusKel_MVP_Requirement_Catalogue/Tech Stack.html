Microsoft Story: We are building sustainability and finance infrastructure for SMEs, lenders, and corporates. Our customers already operate within the Microsoft ecosystem, so we are leveraging Microsoft cloud, AI, analytics, and workflow tools to reduce adoption friction and accelerate enterprise integration.

Development Stack Suggestions
14
The MVP should be delivered as a secure, scalable web application built on the Microsoft ecosystem, with a modular backend, API layer, rule-based scoring engine, and future-ready AI capability. The architecture should support SME data capture, Companies House lookups, funding matching, future open banking integrations, ESG data sources, lender workflows, and corporate reporting use cases.
15
StackSuggestionNote 1Note 2
16
BackendUse .NET / ASP.NET Core or Node.js on Azure App Service for API development and core backend services.For the MVP, avoid heavy microservices too early. Start with a modular monolith where the scoring engine, funding match engine, user management, and reporting logic are separated internally but deployed simply.Use Azure Functions for lightweight background tasks such as score recalculation, document processing, alerts, and scheduled data refreshes.

Use Azure Service Bus later when workflows become more event-driven, such as lender notifications, document reviews, and third-party integrations.
17
FrontendUse React or Next.js for the web application.Use Tailwind CSS or Microsoft Fluent UI for consistent styling and clean dashboard components.The frontend should focus on clear user journeys for SME onboarding, ESG data input, score visibility, funding readiness, and improvement actions.
18
DatabaseUse Azure Database for PostgreSQL as the primary relational database for users, SME profiles, ESG inputs, scoring outputs, funding products, eligibility rules, and audit logs.Use Azure Blob Storage for ESG evidence, uploaded documents, supporting files, and future lender documentation.Use Azure Cache for Redis later for caching score calculations, dashboard data, and funding recommendations when usage grows.
19
Hosting & InfrastructureUse Microsoft Azure as the core cloud platform.Recommended services:

Azure App Service for hosting backend APIs
Azure Static Web Apps or Azure App Service for frontend hosting
Azure Database for PostgreSQL for structured platform data
Azure Blob Storage for documents and ESG evidence
Azure Key Vault for secrets, API keys, and credentials
Azure Monitor / Application Insights for logs, performance monitoring, and error tracking
Microsoft Defender for Cloud for security posture management as the platform scales
20
AI LayerUse Azure OpenAI Service rather than building a proprietary AI model at MVP stage.AI should support:

ESG input interpretation
Explanation of scores
Funding readiness summaries
Suggested improvement actions
Document summarisation
Future ESG data extraction		The core scoring logic should remain rule-based and explainable at MVP stage. AI should assist interpretation, not replace the scoring engine.
21
Identity & AccessUse Microsoft Entra ID / Entra External ID for authentication when the platform becomes more mature.For MVP, keep authentication simple but architect it so that later you can support:

SME users
internal admin users
lender users
corporate users
role-based access control
22
Analytics & ReportingUse Power BI later for advanced reporting, lender dashboards, portfolio insights, and corporate ESG visibility.For MVP, keep reporting inside the web app. Power BI becomes more valuable once you have enough SME and lender data - later phases.
23
Third-Party Services
Use:

Companies House API for company lookup and baseline company data
Open Banking providers such as TrueLayer or Yapily in later phases
ESG data providers in later phases
DocuSign or Adobe Sign for LOIs, lender agreements, and pilot documentation
Microsoft Teams / Outlook integrations later for workflow notifications and enterprise adoption
24
MVP Build PrincipleFor MVP, keep the architecture lean:

React / Next.js frontend
→ Azure-hosted backend API
→ Azure PostgreSQL database
→ Rule-based scoring engine
→ Funding match logic
→ Azure Blob Storage for documents
→ Azure OpenAI for explanations and summaries		The key is not to overbuild the cloud architecture too early. Start simple, but structure it so JusKel can later evolve into a workflow platform for SMEs, lenders, and corporates.

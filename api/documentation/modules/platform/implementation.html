Decided stack

Layer Decision CTO verdict
Frontend Next.js Superior performance and array of configuration to suit modern frontend applications
Backend C# (.NET 10 / ASP.NET Core) Part of the Microsoft ecosystem and battle tested for fintech development; scales well with multi-parallel thread processing
Database SQL Server Relational database on Azure for structured platform data
Storage Azure Blob Storage Agreed — documents and ESG evidence
Infrastructure Microsoft Azure Agreed
AI Azure OpenAI Agreed — assist interpretation, not replace rule-based scoring
Identity Custom auth (MVP) Post-MVP: Microsoft Entra — less than 5% of SMEs use Microsoft OAuth
Analytics In-app reporting (MVP) May explore Microsoft Fabric; Power BI in later phases

Engineering decisions

Modular monolith

Single deployable API with internal module boundaries: scoring engine, funding match engine, user management, reporting logic.

Principle Do not overbuild cloud architecture too early. Structure for evolution into a workflow platform for SMEs, lenders, and corporates.

Scoring engine

Rule-based and explainable at MVP. Azure OpenAI supports summaries and interpretation only.

Monorepo layout

  • api/ — .NET 10 backend
  • client/ — Next.js frontend (Vercel root directory)
  • api/documentation/ — this documentation site

No root package.json — deploy API and client independently.

Health checks /health is in-memory only — no database ping. Keeps Azure SQL Serverless eligible for auto-pause and avoids burning Basic DTU on probe traffic.

Catalogue evolution

The original requirement catalogue listed Python (FastAPI) and Azure PostgreSQL in an early architecture draft. The updated catalogue (with CTO verdicts) confirms Next.js and C# (.NET). The engineering team has further decided on SQL Server as the primary database for this monorepo.

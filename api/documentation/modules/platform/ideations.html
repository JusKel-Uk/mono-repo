Platform — Ideations

Development stack suggestions, design notes, and considerations from the requirement catalogue.

Overview Schematics Ideations Implementation

Backend

Suggestion

Use .NET / ASP.NET Core or Node.js on Azure App Service for API development and core backend services.

Note 1

For the MVP, avoid heavy microservices too early. Start with a modular monolith where the scoring engine, funding match engine, user management, and reporting logic are separated internally but deployed simply.

Note 2

Use Azure Functions for lightweight background tasks such as score recalculation, document processing, alerts, and scheduled data refreshes. Use Azure Service Bus later when workflows become more event-driven.

Frontend

Suggestion

Use React or Next.js for the web application.

Note 1

Use Tailwind CSS or Microsoft Fluent UI for consistent styling and clean dashboard components.

Note 2

The frontend should focus on clear user journeys for SME onboarding, ESG data input, score visibility, funding readiness, and improvement actions.

Database & storage

Suggestion

Use a relational database for users, SME profiles, ESG inputs, scoring outputs, funding products, eligibility rules, and audit logs.

Note 1

Use Azure Blob Storage for ESG evidence, uploaded documents, supporting files, and future lender documentation.

Note 2

Use Azure Cache for Redis later for caching score calculations, dashboard data, and funding recommendations when usage grows.

AI layer

Suggestion

Use Azure OpenAI Service rather than building a proprietary AI model at MVP stage.

AI should support

  • ESG input interpretation
  • Explanation of scores
  • Funding readiness summaries
  • Suggested improvement actions
  • Document summarisation
  • Future ESG data extraction

Key principle

The core scoring logic should remain rule-based and explainable at MVP stage. AI should assist interpretation, not replace the scoring engine.

Identity & access

Suggestion

Use Microsoft Entra ID / Entra External ID for authentication when the platform becomes more mature.

MVP approach

Keep authentication simple but architect it so that later you can support:

  • SME users
  • Internal admin users
  • Lender users
  • Corporate users
  • Role-based access control

Analytics & reporting

Suggestion

Use Power BI later for advanced reporting, lender dashboards, portfolio insights, and corporate ESG visibility.

For MVP, keep reporting inside the web app. Power BI becomes more valuable once there is enough SME and lender data — later phases.

ISO 27001 — Technical Roadmap

Six pillars adjusted for juskel's lean Azure MVP. Enterprise patterns scaled down, not skipped.

In Progress
Overview Control Map Roadmap 90-Day Plan

1. Subscription isolation & IaC

juskel adjustment: Keep one subscription. Split resource groups. Treat deploy-azure.sh as version-controlled imperative IaC until Bicep is ready.

Phase A — now (free)

  • Create rg-juskel-nonprod (current DevTest) and rg-juskel-prod when going live
  • Tag resources: Environment, Owner, DataClassification
  • Export Azure Activity Logs to existing Log Analytics workspace
  • Document environment boundaries in ISMS risk register

Phase B — pre-certification

  • Extract deploy-azure.sh into Bicep modules incrementally (Log Analytics → Container Apps env → app → storage)
  • No AKS, VNets, or NSGs required for MVP — Container Apps + HTTPS is proportionate

Defer

  • Private endpoints for Azure SQL (~$7+/endpoint/month)
  • Azure Policy "deny manual creation" until Bicep is sole deploy path
  • Multi-subscription management groups

2. Zero-trust identity

Two layers: Azure admin identity (your az login) and app user identity (custom JWT — not Entra ID yet).

Azure admin — do now

Control juskel action
MFA on az login Mandatory on Microsoft account / Entra user owning subscription
PIM JIT Owner activation if on Entra P1/P2; else document sole-admin + MFA policy
SQL logins Separate logins per environment; rotate; replace with Managed Identity

App users — document, don't rip out

SoA entry: "A.8.5 — application-layer JWT (issuer/audience validation, 60-min expiry, HTTPS only). Entra ID SSO planned."

Evidence: SignInHandler, OTP verification, JWT config in Container App secrets (not git), Swagger disabled in Production (Program.cs).

Managed identities — high-impact next step

  1. SQL: Authentication=Active Directory Managed Identity — remove password from prod connection string
  2. Key Vault (~£3/mo): Store Jwt__Secret, Resend API key; Container App reads via MI + secretref

System-assigned MI for ACR pull already exists in deploy-azure.sh — extend the same pattern.

3. DevOps & deployment pipelines

Biggest gap. No GitHub Actions today; prod deploys from laptop via deploy-azure.env. Fix before audit.

Minimum viable pipeline

  • On PR: dotnet build + tests + secret scan (gitleaks)
  • On merge to main: OIDC federation to Azure → deploy-azure.sh deploy
  • Branch protection: require status check, no force push, PR required

Enterprise vs juskel MVP

Enterprise juskel MVP
2 reviewers 1 reviewer + CODEOWNERS if team < 3; document in ISMS
Defender for DevOps gitleaks + dotnet list package --vulnerable
Azure DevOps work items Link PR to GitHub Issue
Long-lived AZURE_CREDENTIALS Workload Identity Federation (OIDC) — no stored secrets

4. Encryption & backup

Already in place

  • Azure SQL TDE — enabled by default (Microsoft-managed keys)
  • TLS 1.2+ — Container Apps and database.windows.net
  • Non-root container — USER app in Dockerfile

Actions required

Item juskel action
Customer-managed keys Defer — document Microsoft-managed TDE; revisit for regulated lender data
Public email blob storage Document: static marketing images only, no PII in container
SQL backup Enable automated backup on prod; retention ≥ 7 days
Restore drill Quarterly: restore to juskel-restore-test DB; log RTO/RPO
JWT rotation Document procedure: generate → dual-sign window → revoke old

Target RTO/RPO (prod SQL): RTO 4h / RPO 1h. Email PNGs re-uploadable from juskel.Email/Templates/assets.

5. Logging & monitoring

deploy-azure.sh already creates juskel-dev-logs Log Analytics and wires Container Apps environment.

Now (budget-safe)

  • Add Application Insights (free tier ~5 GB/mo — matches logging filters in Program.cs)
  • Diagnostic settings: Container App + SQL audit logs → same workspace
  • Export Entra sign-in logs for Azure portal access
  • One alert: Container App restart loop or HTTP 5xx spike

App-level logging (before audit)

  • Structured events: user.registered, user.signin.success|failure, otp.sent, otp.verified
  • Correlation ID middleware in juskel.Api
  • Never log connection strings, JWT secrets, or Resend keys

Health check (document for auditors)

/health is in-memory only — intentional. Continuous DB pings prevent SQL Serverless auto-pause and exhaust Basic DTU. See .cursor/rules/dotnet-budget-constraints.mdc.

Defer (cost)

  • Microsoft Sentinel (~$2/GB ingestion)
  • WORM immutable blob log archive — start with Log Analytics 90-day retention

6. Compliance dashboard & audit prep

Defender for Cloud

  • Enable free Secure Score on subscription
  • Assign ISO/IEC 27001:2022 regulatory compliance initiative
  • Expect < 90% initially — fix high-severity first; document accepted risks

GRC tooling

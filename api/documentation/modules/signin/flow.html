Sign-in — Flow

Onboarding, OTP email verification, sign-in gating, and frontend recovery paths.

End-to-end OTP onboarding (master flow)

Every new user must verify inbox ownership before receiving a JWT. OTP codes are hashed in the database; only the plain code is emailed.

Registration → verify → sign-in

Sign-in without verification (403 nuance)

This is the path the frontend must handle explicitly. Valid credentials alone are not enough — the API returns a distinct status so the client can route to the OTP screen.

POST /identity/sessions decision tree
Condition HTTP status Frontend action
Missing / invalid input 400 Show validation errors
Unknown email or wrong password 400 Generic “Invalid email or password” (no account enumeration)
Valid password, emailVerified = false 403 Read errorCode → route to OTP screen; pre-fill email from response
Valid password, emailVerified = true 201 Store accessToken; proceed to app

403 response shape (RFC 7807 ProblemDetails)

{
  "type": "https://juskel.com/problems/email-not-verified",
  "title": "Email not verified.",
  "status": 403,
  "detail": "Email address is not verified. Check your inbox for the verification code.",
  "errorCode": "EMAIL_NOT_VERIFIED",
  "email": "user@company.com"
}

Frontend guard:

if (response.status === 403 && body.errorCode === "EMAIL_NOT_VERIFIED") {
  navigateToOtpScreen({ email: body.email });
}

Resend OTP flow

Triggered from the OTP screen when the user did not receive the code or it expired. Always returns the same message to avoid email enumeration.

POST /identity/verification/resend

Request

{ "email": "user@company.com" }

Response (always)

{
  "message": "If an unverified account exists for this email, a new verification code has been sent."
}

Internally, a new OTP is only issued when the account exists and emailVerified is false. Previous OTP hashes are replaced; expiry resets to 10 minutes.

Verify OTP flow

POST /identity/verification
Verify result HTTP status Detail
Success 200 emailVerified: true — client should retry sign-in
Wrong code 400 Invalid verification code (attempt counter incremented, max 5)
Expired 400 Prompt user to tap Resend
Too many attempts 400 Must request a new code via Resend

Registration flow

POST /identity/users

After registration the frontend should land on the OTP screen immediately — the user cannot sign in until verification succeeds.

Sign-in — Implementation

Identity module endpoints, DTOs, and HTTP contracts (juskel API).

Implemented
Overview Schematics Flow Implementation

Endpoints

Base URL (development): http://localhost:5242 · Swagger: /swagger

Method Route Description Status
POST /identity/users Register user; issues OTP and sends verification email Live
POST /identity/verification Verify email with OTP code Live
POST /identity/verification/resend Resend OTP to unverified account Live
POST /identity/sessions Sign in with email + password (JWT) Live
GET /identity/me Current user (Bearer JWT required) Live
GET /identity/users/{id} User summary by id Live

HTTP status codes (sign-in & OTP)

Endpoint Code When
POST /identity/users 201 User created; OTP emailed
POST /identity/sessions 201 Authenticated + email verified → JWT returned
POST /identity/sessions 403 Valid password but emailVerified = false → errorCode: EMAIL_NOT_VERIFIED
POST /identity/sessions 400 Invalid credentials or validation error
POST /identity/verification 200 OTP accepted; user marked verified
POST /identity/verification/resend 202 Always — generic success message (anti-enumeration)

Request / response DTOs

RegisterUserRequest → RegisterUserResponse (201)

  • firstName, lastName, email, password
  • Response: userId, email, emailVerified (always false on create)

VerifyEmailRequest → VerifyEmailResponse (200)

  • email — string, required
  • otpCode — string, accepts 482917 or 482 917
  • Response: userId, email, emailVerified

ResendOtpRequest → ResendOtpResponse (202)

  • email — string, required
  • Response: message — generic confirmation string

SignInRequest → SignInResponse (201)

  • email, password
  • Response: userId, accessToken (JWT)

Email & OTP internals

Component Project Role

Default sender: juskel <hello@juskel.co.uk> via Resend in production.
